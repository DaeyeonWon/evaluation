# i18n: KO/EN localization

The console ships in **Korean (`ko`) and English (`en`)** and has a KO | EN toggle. Every screen gets a
complete English version. The Korean version keeps technical terms, proper nouns and service/system
names in English. Only ordinary UI language is Korean.

> Requirement: "글로벌로도 사용해야되니 한영 전환도 하게 해주고 전체페이지를 완전 영어버전도 준비해.
> 한글버전은 굳이 모든걸 한글로 할 필요는 없고 고유 기술이름, 명사나 서비스 시스템 이름 등은 영어를 잘 살리는게 더 좋아."

The implementation is a small typed layer in `src/i18n/` with no dependencies (rationale in §10).

## 1. Quick reference

| Where | Import | API |
| --- | --- | --- |
| Client component | `@/i18n/client` | `useT(ns)`, `useLocale()`, `useFmt()`, `useSetLocale()` → `{ locale, setLocale, isPending }`, `useI18n()`, `I18nProvider`, `writeLocaleCookie()` |
| Server component, layout, `generateMetadata` | `@/i18n/server` | `await getLocale()`, `await getT(ns)`, `await getFmt()`, `await getI18nProps()` |
| Route handler, `proxy.ts`, `http.ts` | `@/i18n/request` (no `next/headers`) | `localeFromRequest(req)`, `tFor(req, ns)`, `translatorFor(locale, ns)`, `getMessages(locale)` |
| Anywhere: reference data (status, catalog) | `@/i18n` (= `@/i18n/static`) | `statusLabel(family, value, locale)`, `statusHelp`, `stageLabel`, `stageService`, `stageDescription`, `componentLabel`, `eventLabel`, `capsuleLabel`, `deviceLabel`, `languageName`, `failureCategoryLabel`, `failureCategoryPolicy`, `failureReasonLabel`, `staticT(locale, "status" \| "catalog")` |
| Config | `@/i18n/config` | `DEFAULT_LOCALE`, `LOCALE_DETECTION`, `negotiateLocale()`, `resolveLocale()` |
| UI | `@/components/shared` | `<LocaleToggle />`, `statusInfo(kind, status, locale)`, `createFmt(locale)` |

```tsx
// client component
"use client";
import { useT, useFmt } from "@/i18n/client";
const t = useT("dlq");
const f = useFmt();
<h2>{t("title")}</h2>
<p>{t("selected", { count: ids.length })}</p>          // en "3 items selected" via plural forms
<td>{f.relative(d.created_at, now)}</td>               // "3분 전" / "3m ago"

// server component or generateMetadata
import { getT } from "@/i18n/server";
export async function generateMetadata() {
  const t = await getT("nav");
  return { title: t("overview.title") };
}

// route handler
import { tFor } from "@/i18n/request";
throw notFound(tFor(req, "errors")("domain.workflowNotFound", { id }));

// reference data, no hooks (chart option callbacks, CSV, utils)
import { statusLabel, capsuleLabel } from "@/i18n";
series.name = statusLabel("workflow", s, locale);      // "Running"
```

**Locale resolution** (`getLocale`, `localeFromRequest`):

1. cookie `console_locale` (`ko` or `en`), the user's explicit choice from the toggle
2. `Accept-Language`, weighted by q and matched on the primary subtag (`en-GB` → `en`). Set `CONSOLE_LOCALE_DETECTION=0` to skip this step.
3. `DEFAULT_LOCALE`, which is env `CONSOLE_DEFAULT_LOCALE` if valid, else `ko`

The cookie is `Path=/; Max-Age=1y; SameSite=Lax` and is not httpOnly, because the client writes it. `fetch('/api/v1/…')` is same-origin, so it sends the cookie and **API errors come back in the UI locale automatically**.

## 2. Glossary: terms that stay English in the Korean UI

The rule: if a term is the name of a **system, service, product, protocol, data field, or platform concept that an operator would search for in logs, code or GCP**, keep it in English in both locales. Write it with its canonical casing. Korean particles attach directly to it ("Workflow를 취소합니다", "Slot이 부족합니다").

| Group | Terms (exact spelling) |
| --- | --- |
| Platform concepts | Workflow, PipelineJob, Pipeline, DAG, Node, Task, Component, Stage (in system names), DLQ, Dead letter, Replay, Replay Cycle, Cycle, Attempt, Retry, Backoff, Admission, Capacity, Slot (Capacity Slot), Reservation, Fencing token, Backlog, Pending Queue, Queue, Priority, FIFO, Batch, Event, CloudEvent, Event type, Trace ID, Correlation ID, Idempotency Key, Timeout, Reconciler, Scheduler, Dispatcher, Ingress, Event Ingress, Registry, Drift, Dry run, Mock, Canary, Stable, Deprecated |
| GCP and services | GCP, Cloud Run, Cloud Workflows, Vertex AI, Vertex AI Pipeline, Firestore, Pub/Sub, Eventarc, BigQuery, GCS, Cloud Storage, Cloud Logging, IAP, OIDC, Terraform, L4 / GPU, machine types (`n2-standard-8`) |
| Evaluation domain | Bixby, Bixby Agent, Capsule, Intent, Slot (NLU slot), ASR, LLM Judge, Judge score, PASS / FAIL, Utterance ID, p50 / p95, SLO, Latency Check, Intent Eval, Response Eval, Preprocess, Aggregate, Persist |
| Products and devices | Galaxy S26, Galaxy Watch, Galaxy Buds, TV, Family Hub, SmartThings |
| Console and app names | AIPO, Atlas, Hermes, Explorer, Capacity (screen), DLQ (screen), MOCK DATA |
| Roles and permissions | Admin, Operator, Viewer (role names), permission keys (`config.write`, `replay.request`) |
| Status enums | see §3.1 |
| Always raw, never translated | IDs (`wf-20261112-ko-0033`), error codes (`QUOTA`, `INVALID_ARGUMENT`), Event type constants (`RETRY_SCHEDULED`), API field and CSV column names (`pipeline_job_id`, `failure_reason`), GCS URIs, log lines from the engine, severity values (`ERROR`), units (`ms`, `s`, `KB`) |

**Ambiguity: Slot.** "Slot" means two things: an execution **Capacity Slot** (Scheduler) and an **NLU slot** (Intent/Slot evaluation). Wherever the context is not obvious, write "Capacity Slot" or "Intent/Slot".

**Generic actions vs platform concepts.** The *platform concept* stays English: "Retry 예약", "Replay 요청", "Workflow 취소". The *generic UI verb* is Korean: a button "다시 시도" (try a failed fetch again), "취소" (close a dialog). Do not label a generic "try again" button "Retry", because operators would read it as a platform Retry.

## 4. Tone

**English**: sentence case ("Reset filters", not "Reset Filters"), active voice, concise. Use contractions in messages ("Couldn't load data", "You don't have permission"). Don't end labels with a period. End full-sentence messages with one. Prefer verbs on buttons ("Replay 3 items", "Cancel Workflow"). Use the en dash for ranges ("1–10"). Avoid "please", except in rare destructive confirmations.

**Korean**:
- **Labels, buttons, table headers, tabs** end in a noun with no 다/요 ending: "저장", "필터 초기화", "Workflow 취소", "검토 대기".
- **Messages** (toasts, errors, empty states, help text, confirmations) use **합니다체**: "취소했습니다", "데이터를 불러오지 못했습니다", "사유를 입력해 주세요". Don't use 해요체. Don't use 한다체; the old catalog descriptions used it and were rewritten.
- Put interpolated identifiers **after a colon**, so the particle never depends on the value: "Workflow를 찾을 수 없습니다: {id}". When a value must come before a particle, use a neutral noun: "{name} 값은 정수여야 합니다", not "{name}는".
- Attach particles directly to English terms, choosing them by the pronunciation of the English word: "Workflow를", "Slot이", "Replay가", "DLQ에".

**Both**: numbers always use digits ("3건", "3 items"). Don't build sentences by concatenating translated fragments. Put the whole sentence in one message with `{placeholders}`, because word order differs between the languages.

## 5. Numbers, dates and times

| What | ko | en | API |
| --- | --- | --- | --- |
| Timezone | **Asia/Seoul in both locales**; show "KST" wherever a date and time appear together | same | all `fmt.*` |
| Numbers | 2,400 · 87.5% · 1.50 KB · $12.40 | identical | `fmt.number/pct/bytes/usd` (locale-independent) |
| Time | 14:31:05 · 14:31 | identical (24-hour) | `fmt.time/hm/timeMs` |
| Date (machine) | 2026-11-12 · 2026-11-12 14:31:05 | identical | `fmt.date/dateTime/iso` |
| Date (label) | 11월 12일 (목) | Thu, Nov 12 | `f.dateLabel(ts)` (`fmt.dateKo` is the ko alias) |
| Date + time (label) | 11월 12일 14:31 KST | Nov 12, 14:31 KST | `f.dateTimeLabel(ts, { seconds?, tz? })` |
| Duration | `style:"short"` gives **11m 49s · 4.2s · 1h 05m in both**; long gives 11분 49초 | long gives 11m 49s (en has no long form) | `f.duration(ms, { style })` |
| Relative | 방금 · 12초 전 · 3분 전 · 2시간 후 | just now · 12s ago · 3m ago · in 2h | `f.relative(ts, useSimNow())` |
| Counts with units | Workflow 3개 · 3건 | 1 workflow / 3 workflows | message plural forms (§6) |

- Get the locale-bound set from `useFmt()` (client), `await getFmt()` (server) or `createFmt(locale)`. They have the same members as `fmt`, with the locale already applied.
- Existing calls such as `fmt.duration(ms, { style: "short" })`, `fmt.relative(ts, now)` and `fmt.dateKo(ts)` keep their exact old output (ko default). `src/server/mock/engine.ts` is unaffected.
- Recommended: use `style: "short"` durations in tables and cards, because they read the same in both locales.
- Relative times must use the simulator clock `useSimNow()`, never `Date.now()`.

## 6. Adding and using strings

### 6.1 Files

```
src/i18n/messages/
  index.ts          NAMESPACES + bundles (server import only)
  ko/<ns>.ts        the SCHEMA: plain object, string leaves, no `as const`
  en/<ns>.ts        `{ … } satisfies Messages<typeof ko>`
```

Each area has its own namespace so that parallel work doesn't conflict: `common`, `nav`, `shell`, `orchestration` (canvas), `inspector`, `board`, `overview`, `capacity`, `explorer`, `workflow` (detail), `pipelines`, `dlq`, `results`, `analytics`, `config`, `files`, `auth`, `hermes`, `errors`, `status`, `catalog`.

- **Pre-filled**: `common`, `nav`, `status`, `errors`, `catalog`.
- **Empty, for page engineers**: all the others. Each file has a header comment that says which component it serves.

### 6.2 Add a string

1. Add the key to `ko/<ns>.ts`. Nest by UI region: `filters.status`, `table.columns.wait`, `dialog.replay.title`.
2. Add the same key to `en/<ns>.ts`. TypeScript reports a missing **or** an extra key at the `satisfies` line.
3. Use it: `t("dialog.replay.title")`. Keys are typed, so a typo is a compile error, and the editor autocompletes them.
4. Run `node --experimental-strip-types src/i18n/check-messages.ts`. It checks key parity, leaf types, and that every locale uses the same `{placeholders}`.

Syntax:

```ts
// ko
selected: "{count}건 선택됨",
replayN: "{count}건 Replay",
// en: a plural object is selected with Intl.PluralRules by `count`; # = formatted count
selected: "{count} selected",
replayN: { one: "Replay # item", other: "Replay # items" },   // zero?: "…" optional
```

- `{name}` interpolates `vars.name`. Numbers get thousands separators. An unknown placeholder renders as-is. Write `{{` and `}}` for literal braces.
- Korean never uses plural objects; the check enforces this.
- An object with string `one` **and** `other` keys counts as a plural leaf. Never name a group with exactly those keys. A group that merely contains `other` (`{ quota: "…", other: "기타" }`) is fine.
- Dynamic keys type-check against unions: ``t(`workflow.${status}.label`)`` compiles when `status: WorkflowStatus`. For a truly runtime key, use `t.dynamic(key, vars, fallback)`. `t.has(key)` tests for a key without logging a warning.
- **A missing key** renders `"ns.key"` and logs one `console.warn` in development.
- Rich text and JSX are not built in. Split the text around the element (`t("hint.before")`, `<b>…</b>`, `t("hint.after")`), or keep the markup outside the message.

### 6.3 Use it

```tsx
// client
const t = useT("capacity");             // memoized, safe in effect deps
const locale = useLocale();             // pass to static helpers, Intl, chart options
const f = useFmt();

// ECharts option functions run outside React: read the locale in the component and close over it
const locale = useLocale();
<EChart option={(tk) => ({ series: STATES.map((s) => ({ name: statusLabel("workflow", s, locale), … })) })} />

// server component / generateMetadata
const t = await getT("results");
const locale = await getLocale();

// route handler
const t = tFor(req, "errors");
```

Don't import `@/i18n/server` or `@/i18n/messages` from a `"use client"` file. They pull in `next/headers` and every bundle. (`server-only` is not installed, so nothing will stop you.)

## 7. Integration steps (owners: B, A, shell/page engineers)

### 7.1 Root layout (`src/app/layout.tsx`, owner B): required

Shown against B's current layout (SessionProvider + session-gated LiveStream). Only the lines marked `// i18n` are new:

```tsx
import type { Metadata, Viewport } from "next";
import { fontVariables } from "@/fonts";
import { ThemeProvider, ThemeScript } from "@/components/shared/theme";
import { LiveStreamProvider } from "@/lib/client/live-stream";
import { SessionProvider } from "@/lib/client/session";
import { getSession, sessionInfo } from "@/server/auth";
import { I18nProvider } from "@/i18n/client";            // i18n
import { getI18nProps, getT } from "@/i18n/server";      // i18n
import { LOCALE_META } from "@/i18n/locales";            // i18n
import "./globals.css";

// i18n: replaces the static `export const metadata`
export async function generateMetadata(): Promise<Metadata> {
  const t = await getT("common");
  return {
    title: { default: `${t("app.productName")} · ${t("app.subtitle")}`, template: `%s · ${t("app.productName")}` },
    description: t("app.consoleName"),                   // or add a dedicated key
    robots: { index: false, follow: false },
  };
}

export default async function RootLayout({ children }: LayoutProps<"/">) {
  const [session, { locale, messages }] = await Promise.all([getSession(), getI18nProps()]);   // i18n
  return (
    <html lang={LOCALE_META[locale].htmlLang} className={fontVariables} suppressHydrationWarning>  {/* i18n */}
      <head><ThemeScript /></head>
      <body>
        <I18nProvider locale={locale} messages={messages}>  {/* i18n: outermost */}
          <ThemeProvider>
            <SessionProvider initial={sessionInfo(session)}>
              {session ? <LiveStreamProvider>{children}</LiveStreamProvider> : children}
            </SessionProvider>
          </ThemeProvider>
        </I18nProvider>
      </body>
    </html>
  );
}
```

- `I18nProvider` must wrap everything that renders text, including `SessionProvider` and toasts. Put it outermost inside `<body>`.
- Reading `cookies()` in the root layout makes every route dynamic. `cacheComponents` is off, so this only changes the build output; the pages are live-data client screens anyway.
- `<html lang>` follows the locale on the first render. `setLocale()` also sets `document.documentElement.lang` immediately, and `router.refresh()` re-renders the layout.
- The (console) layout and page `metadata` objects are static Korean today. Page engineers should switch them to `generateMetadata` + `getT("nav")` (`nav.<screen>.title`).
- Until this lands, `StatusPill`, `SeverityBadge` and `LangBadge` still work (they fall back to ko through the static tables), but `useT()` callers render keys and one dev warning appears.

### 7.2 API errors (`src/server/http.ts`, owner B; services owner A)

All current messages already have keys in `errors.*`: `code.*`, `validation.*`, `permission.*` and `domain.*`. Suggested shape:

```ts
// http.ts
import { tFor, translatorFor } from "@/i18n/request";
import type { Vars } from "@/i18n";

export type ErrorText = string | { key: string; vars?: Vars };   // key under the "errors" namespace

export class ApiError extends Error {
  constructor(public status: number, public code: string, public text: ErrorText, public details?: unknown) {
    super(typeof text === "string" ? text : text.key);
  }
}
export const badRequest = (m: ErrorText, details?: unknown) => new ApiError(400, "INVALID_ARGUMENT", m, details);
// … notFound / conflict / forbidden / unauthorized likewise

export function errorResponse(e: ApiError, req?: Request): Response {
  const t = req ? tFor(req, "errors") : translatorFor("ko", "errors");
  const message = typeof e.text === "string" ? e.text : t.dynamic(e.text.key, e.text.vars, t.dynamic(`code.${e.code}`));
  const key = typeof e.text === "string" ? undefined : e.text.key;
  return Response.json({ error: { code: e.code, message, ...(key ? { key } : {}), ...(e.details !== undefined ? { details: e.details } : {}) } }, { status: e.status, headers: NO_STORE });
}
// handle(): pass req → errorResponse(e, req); the 500 path → { key: "code.INTERNAL" }
```

Call sites:

```ts

throw badRequest({ key: "validation.range", vars: { name: label, min, max } }, { field: key, min, max });
throw notFound({ key: "domain.workflowNotFound", vars: { id } });

```

- A plain string still works (backwards compatible), so services can migrate one file at a time.
- For a label used as `{name}`, pass the field name (`max_concurrent`) or a key resolved with the same translator, such as `t("validation.reasonLabel")`.
- `src/lib/client/api.ts` (owner A): replace the Korean fallback `요청이 실패했습니다 (${status}).` with the server's `message`. If no body came back, use `errors.client.requestFailed`. - The default cancel reason "운영자 요청에 의한 취소" is stored in data. It now has the key `domain.defaultCancelReason`. Decide whether stored audit text should stay ko; recommended: store the code and render it localized.

## 9. Fonts and English layout

- **SUIT Variable** (`--font-atlas-sans`) is the Atlas UI font and includes a complete Latin set. English renders in the same face, so you don't need another font or any change to the font loading. **IBM Plex Mono** (`--font-atlas-mono`) renders IDs, code and numbers in both locales.
- `<html lang>` now switches, so locale-specific CSS can use `:lang(en)` or `:lang(ko)`. For example, Korean blocks can keep `word-break: keep-all` and English can use `hyphens: auto` in long descriptions.
- Watch for these in English: longer button labels, truncation in tab bars and KPI tiles, and plural forms that change width.

## 10. Design notes and limits

- **Why no library.** next-intl and similar libraries add a plugin, middleware or routing conventions, and their Next 16 support would need verification. The needs here are two locales, typed keys, interpolation and en plurals. A ~150-line core plus a provider covers them with no hydration risk: the server picks the locale and passes that one locale's bundle to the provider. `Intl.PluralRules` handles plural selection.
- **Bundle.** The provider receives every namespace of the active locale. It is serialized in the RSC payload of the root layout, which soft navigation doesn't re-send; `router.refresh()` does. The `status` and `catalog` tables are bundled in both locales (a few KB) so shared components work without a provider. If the messages grow large, the upgrade path is per-namespace loading in nested layouts with a second `I18nProvider` that merges namespaces.
- **What stays untranslated by design:** engine log lines (English system output), Event payloads, API field names, CSV columns and values, error `code`s, IDs.
- **Checks:** `satisfies` catches missing and extra keys at compile time. `src/i18n/check-messages.ts` catches parity, leaf-type and placeholder drift at run time. Typed `t()` keys catch typos.
- **Not built:** rich-text/JSX interpolation, ICU `select`, locale-prefixed URLs and a per-user server-side preference. The cookie is per browser.
